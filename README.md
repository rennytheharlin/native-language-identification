# Native language identification from Indian English speech

This project compares two speech representations on the same five-way NISP native-language task: MFCC features and frozen HuBERT layer-6 features. Both use the same 128-unit MLP classifier and the same speaker-disjoint split. All project implementation code is in the four Jupyter notebooks.

## Run order

Open a terminal in this directory and select the `Python 3.12 (speech-nli)` kernel.

1. `00_prepare_data.ipynb` streams the English archives, audits labels, and writes `data/manifest.csv`.
2. `01_extract_features.ipynb` creates cached MFCC and HuBERT vectors.
3. `02_train_models.ipynb` trains both classifier heads with validation-only checkpoint selection.
4. `03_results.ipynb` evaluates the untouched test speakers and writes plots and metrics to `results/`.

The notebooks resume extraction and feature caching if rerun. Start them from this directory so `Path.cwd()` resolves to the project root. The original dataset stays at `C:\Users\renny\Desktop\projects\speech proj\NISP-Dataset-master`; adjust `SOURCE` in the first notebook if it moves.

## Environment

The local virtual environment is `.venv`, using Python 3.12. Recreate it on Windows with `uv venv --python 3.12 .venv`, `uv pip install --python .venv\Scripts\python.exe torch==2.8.0 torchaudio==2.8.0 --index-url https://download.pytorch.org/whl/cu128`, then `uv pip install --python .venv\Scripts\python.exe -r requirements.txt`. Check the current [PyTorch selector](https://pytorch.org/get-started/locally/) if the CUDA wheel needs to change for another machine. The notebook kernel must point to that environment. Final HuBERT feature extraction and classifier training require PyTorch CUDA access to the RTX 4060 and fail clearly if it is unavailable.

## Protocol

- English speech only; Hindi, Kannada, Malayalam, Tamil, and Telugu mother-tongue classes.
- Folder labels are accepted only when the speaker metadata agrees, allowing unambiguous case and spelling variants. Of 345 metadata speakers, 314 meet this rule and 31 do not.
- Official NISP test speakers remain held out. A stratified 20% validation sample comes only from eligible official training speakers, with seed 42.
- All valid utterances from eligible speakers are retained. A missing transcript ID is flagged, not used as a label, and does not discard otherwise valid English audio.
- Both classifiers train on the same utterances. Class and speaker weights prevent speakers with more files from dominating the training loss.
- Speaker macro-F1 is the primary result. Speaker probabilities are the mean of that speaker's utterance probabilities. The paired bootstrap uses 2,000 class-stratified speaker resamples.

The supplied archive parts are concatenated virtually and decoded through two gzip layers; no joined archive is written. Only eligible English WAV files are extracted. Approximately 13,310 valid utterances from 314 speakers were found on the initial data run.

## Results and provenance

`results/RESULTS.md`, `results/summary.json`, `results/predictions_*.csv`, and `results/figures/` are generated by the final notebook. Preliminary numbers in `speech_mid.pptx` lack matching saved runs in the original project, so they are not used as results. The Humayun et al. reference paper used a vowel-specific ensemble with ten random speaker splits; its published scores are not directly comparable with this simpler official-split experiment.
